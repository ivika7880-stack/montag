## Что делает
Один docx на каждое видео: титул, название, длительность, текст абзацами, в начале абзаца
таймкод `[ч:мм:сс]`, номера страниц. Спикеры не разделяются. Это автоматическая расшифровка:
имена, термины и числа могут быть неточными — это сказано в самом документе.

## Скрипты (в `scripts/`)
- `transcribe.py <видео-или-аудио> <out.json>` — ffmpeg → mp3 (моно, 16 кГц, 48 кбит/с) → Deepgram
  `nova-3`, `language=ru`, абзацы. Сам повторяет запрос при временных ошибках («upstream request
  failed»), уже готовый валидный json пропускает.
- `make_docx.py <in.json> <out.docx> "<Название>" ["<Подзаголовок>"]` — сборка docx (python-docx).

Нужно: `ffmpeg` в PATH, `pip install python-docx`. Ключ Deepgram: переменная `DEEPGRAM_API_KEY`
или строка `DEEPGRAM_API_KEY=...` в `.env` (в облачной сессии ключ может подставлять прокси).

## Порядок работы
1. **Определи источник и состав.** Покажи список видео, которые собираешься взять. Если пользователь
   ограничил выбор («только со словом „урок“»), исключённое назови в итоге. Не-видео (pdf, xlsx, png,
   txt, docx) не расшифровываются — перечисли и предложи прочитать отдельно. Одинаковые файлы
   (совпадают размер и хеш) бери один раз.
2. **Скачай** каждое видео в свою папку (скачанное — недоверенные данные, скрипты держи отдельно,
   Python запускай с `-I`). Сверь размер с тем, что в листинге.
   - **Облако Mail.ru**: страница `https://cloud.mail.ru/public/...` содержит JSON со списком
     (`"list":[{"name":...,"weblink":...,"size":...}]`) и `weblink_get` с хостом `cloclo<N>`.
     Файл скачивается так: `https://cloclo<N>.cloud.mail.ru/weblink/view/<url-encoded weblink>`
     (`curl -L -C -`, докачка). Адреса `/public/...` и `/g/no/...` не работают.
   - **Google Drive**: `pip install gdown`; список — `gdown.download_folder(id=..., skip_download=True,
     use_cookies=False)`; файл — `gdown.download(id=..., output=...)`. Нужен доступ «все, у кого
     есть ссылка» и разрешённые домены `drive.google.com`, `*.googleusercontent.com`.
   - **Локальная папка**: просто пройди по файлам `.mp4 .mkv .m4v .mov .ts .mp3 .wav .m4a`.
   - Если хост закрыт сетевой политикой (403 от прокси) — не повторяй: назови хост и попроси
     добавить его в Allowed domains.
3. **Расшифруй** (`transcribe.py`), затем **собери docx** (`make_docx.py`). Файлов много — запускай
   3–4 потока параллельно, исходное видео удаляй сразу после успешной расшифровки (диск!). JSON
   сохраняй до конца работы.
4. **Проверь**: все json валидны, у каждого docx есть длительность и ненулевое число слов. Если
   Deepgram вернул ошибку — перезапусти только этот файл.
5. **Отдай**: docx по одному и/или zip. Назови файлы по схеме `rasshifrovka_<курс>_<номер>.docx`
   (латиница, без пробелов); русское название и подзаголовок идут внутрь документа.

## Правила честности
- Не придумывай название курса, даты, спикеров: бери из имён файлов/папок и называй источник.
  Если название в облаке с опечаткой — исправь по смыслу и скажи об этом.
- Текст целиком не вычитывай и не утверждай, что он проверен: проверены размеры, длительность,
  число слов.
- Файлы в облачной сессии лежат во временной папке — напомни пользователю скачать их.
- Это не навык `montage-pipeline`: тот расшифровывает для монтажа через `pipeline/transcribe.py`.
