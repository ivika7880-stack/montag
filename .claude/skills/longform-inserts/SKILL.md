# Длинный ролик с вставками (алгоритм «Prism Rondo»)

Это зафиксированный порядок работы, который мы прошли на разборе «Призма любви» (35 минут, 442 вставки).
Когда Вика пишет «делаем длинный ролик с вставками», идём по нему целиком, ничего не придумывая заново.
Правила проекта (`CLAUDE.md`) в силе: рендер и пуш только по команде Вики, звук голоса не обрабатываем.
Скрипты-образцы лежат в `scripts/` (пути и имена `prism` заменить на `<id>`). Чек-лист проверки — `docs/QC_CHECKLIST.md`.

## 0. Что спросить у Вики перед стартом (один раз, списком)
1. Её **уже смонтированный** ролик (вырезки, паузы, звук сделаны ею). Монтаж голоса НЕ повторяем: берём её файл как есть.
2. Откуда брать вставки: папка с сериями/фильмом (есть ли русские субтитры внутри mkv: `ffprobe`).
3. Как делится видео по героям/частям (по расшифровке находим фразы-границы: «Теперь смотрим на Лилию…»).
4. Раскладка: по умолчанию как в её референсе — слева кадры 70%, справа она 30%.
5. Музыка: файл(ы) в `исходники\music` (лицензию трека проверяет она).
6. Имена героев как произносит она (в субтитрах бывают другие: «Син» у неё = «Шин» в субтитрах).

Её решения по умолчанию (подтверждены в Prism Rondo): вставки короткие 3–5 с; чем больше говорим о герое, тем больше его в кадре; в первое упоминание в кадре именно он; левая панель всегда в движении (не «картинка»); музыка 12%; вдохи не трогаем; цвет выровнен.

## 1. Подготовка окружения (один раз на машине)
- Python 3.11 + `.venv` (`requirements.txt`), ffmpeg, 7-Zip, `venv_clip` (torch + open_clip_torch + opencv 4.10 headless).
- Модель CLIP ViT-B/32 качается при первом запуске (спросить разрешение). Детектор лиц `lbpcascade_animeface` НЕ годится (не находит профили).
- Windows: пути с кириллицей — скрипты `.ps1` сохранять **с BOM**; не называть переменные `$fc`/`$n` (алиасы и регистр).
- ffmpeg 9: файл фильтра `-/filter_complex file`, не `-filter_complex_script`. Не собирать больше ~25 входов в одном графе: резать клипы по одному, потом concat.

## 2. Расшифровка её ролика
`ffmpeg … audio.wav (16 kHz mono)` → `pipeline/transcribe.py` → `words.json`, `utterances.txt` (Deepgram, ключ в `.env`; файл должен называться `.env`, не `.env.txt`).
Находим границы частей (по словам) и конец голоса.

## 3. Субтитры и движение серий
- Из mkv: `ffmpeg -i ep.mkv -map 0:s:0 ep.srt` → общий `subs_all.txt` (серия, время, длительность, реплика).
- `scripts/01_motion.py`: движение по 1/6 с для каждой серии (4 процесса параллельно, ~3 мин на серию).
- `scripts/02_who_is_in_frame.py`: CLIP zero-shot по кадру 1 раз в секунду (центральная панель 1344×1080 → 224): кто в кадре по текстовым описаниям (блондин, девушка с хвостом…, плюс «дистракторы»: рыжая, красноволосый, блондинка, пейзаж, толпа). ~1,5 мин на серию.

**Ворота 1:** показать Вике лист эталонных кадров каждого героя (3–4 кадра, подписанные ep/время), она подтверждает. Проверить на эталонах, что вероятность героя ≥ 0,75.

## 4. План вставок (`scripts/03_plan_and_select.py`)
- Слоты по границам фраз: 3,0–5,0 с (конец слота на знаке препинания или паузе ≥ 0,25 с; не длиннее 5,3).
- Цель слота: герой части по умолчанию; если в слоте названо имя другого героя — он. «Первое упоминание» (Кит / Лилия / Син) — строгий отбор.
- Отбор окон: сначала герой чётко (P ≥ 0,6, минимум ≥ 0,35) и движение (≥ 50% шагов > MOVE=1,0), не более 1 жёсткой склейки; дальше ступенями ослаблять (0,5 / 0,4 / 0,3). Один эпизод подряд не берём, ±12 с от уже взятого блокируем.
- Сначала пробные первые 2–3 минуты, показать Вике, потом остальное. Спойлеры по сериям: спросить, нужна ли защита.

**Ворота 2:** пробные 2:37 одобрены.

## 5. Нарезка и сборка
1. `scripts/05_cut_clips_and_concat.ps1`: каждый клип отдельно (`fps=30,scale=-2:1080,crop=1344:1080`, кадров = `round(t1*30) − round(t0*30)` — накопительным округлением, иначе дрейф), потом `concat -c copy`. Проверять число кадров каждого клипа (бывают пустые).
2. Её панель: HEVC с телефона декодируется с ошибками на нестабильном железе → кодировать кусками по 5 минут (`-ss k*300`, 9000 кадров), каждый кусок проверять `08_scan_panel_glitches.py` и по числу кадров, повторять при сбое.
3. Цвет: её панель `curves=all='0/0.03 0.12/0.20 0.3/0.36 0.5/0.52 0.8/0.8 1/1',colorbalance=rm=-0.08:rh=-0.04`; вставки — `04_grade_params.py` (гамма к средней яркости 0,427, не больше ±30%, насыщенность не выше 150). Сначала проба 30 с «до/после» и «ок» Вики.
4. Финал: `06_grade_and_final_chunks.ps1` — 7 кусков по 9000 кадров, `setpts=N/(30*TB)` для ровных 30 к/с, hstack (слева вставки, справа она 576×1080, кроп `crop=576:1080:15:0` от `scale=-2:1080`). Низкий приоритет, `-threads 2` — машина Вики может зависать под полной нагрузкой.
5. Звук: голос из её файла без обработки; музыка отдельной дорожкой.
   - Музыка 12% (`volume=0.12`), трек по кругу: у каждого экземпляра срезать затухающий хвост и тихий вход (`atrim=1.5:158` для 238726), стык `acrossfade=d=3`, вход 3 с, затухание последних 6 с. **Длину трека мерить ffprobe**, а не на глаз (однажды перепутали 2:48 и 3:48 — музыка оборвалась на 27-й минуте).
   - Итоговый микс линейно −2 дБ (пик исходника +0,4 dBTP): −18 LUFS, пик ≤ −1 dBFS.
   - Видео копируем (`-c:v copy`), звук кодируем один раз.
6. Не перезапускать скрипты поверх старых результатов вслепую: скрипт может молча взять готовый старый кусок. После пересборки проверять результат.

## 6. Правки по запросу Вики (после просмотра)
- Фраза/слово: вырезка по звуку (`07_cut_voice_example.py`) + то же число КАДРОВ из обеих панелей; всё дальше сдвигается на N/30 с; музыку пересводим на новую длину. Проверять распознаванием (ASR), на слух решает Вика; предложить варианты A/B образцами.
- Искажение кадра: найти интервал сканом, перекодировать затронутый 5-минутный кусок, пересобрать финальный кусок (`09_fix_corrupted_chunk_example.ps1`), снова скан.
- Заглушать «вдохи» автоматически НЕ делать: шипящие согласные и вдохи по звуку неотличимы, автоматика съедает слова (была ошибка «ощущений»).

## 7. Проверка перед словом «готово» (обязательно)
`pipeline/qc_video.py` + ручные пункты из `docs/QC_CHECKLIST.md`. Любой FAIL = не готово. В ответе перечислить, что проверено и чем, и отдельно что остаётся на прослушивание Вике.

## 8. Тексты и публикация
- Пост/анонс для Telegram: скилл `moy-golos` (раздел 14 «Анонс видео-разбора для Telegram») + `kontent-dvizhok`. Подпись у Вики Premium: до 4096 знаков.
- Описание для YouTube и теги: скилл `publish-pack`.
- Файл отдаём путём (`out\…mp4`), ничего не публикуем без её команды.

## Ловушки (всё это уже случалось)
- «Картинки» на левой панели: аниме экономно анимировано, брать окна с движением, иначе половина кадров замёрзшая (после отбора 23% — это перевод 24→30 к/с).
- Музыка не на всю длину; провалы на стыках повторов трека.
- Пик звука выше нуля (источник +0,4 dBTP).
- Мозаика на кофте после ошибки декодера HEVC (случайная, при нестабильной памяти).
- Рассинхрон после вырезки слова, если резать звук и кадры на разное время.
- Названия героев в речи ≠ в субтитрах; серии могут быть без нужных сцен — слабые слоты честно показывать Вике (процент слабых по частям).
- Старые версии файлов не удалять без её слова.
